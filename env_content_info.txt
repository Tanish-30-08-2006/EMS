================================================================================
UNDERSTANDING ENVIRONMENT VARIABLES & GIT SECURITY
================================================================================

1. WHAT IS AN .ENV FILE?
   - FULL FORM: The ".env" extension stands for "Environment".
   - MEANING: It is a plain-text file used to store "Environment Variables"—
     settings that change depending on where the app is running (on your PC,
     on a server, or in production).

2. WHY KEEP IT PRIVATE?
   - SECURITY: An .env file contains sensitive "secrets" like your:
     * Database passwords
     * API secret keys (like JWT_SECRET)
     * Email/SMTP passwords (like your Google App Password)
   - RISK: If you upload your .env file to GitHub, anyone can see your secrets.
     Hackers use "bots" to scan GitHub for these files to steal data, delete
     databases, or send spam emails from your account.

3. WHAT IS THE .ENV.EXAMPLE FILE?
   - TEMPLATE: Since the real .env is private, we provide an ".env.example" file.
   - PURPOSE: It is a non-sensitive template that shows other developers
     ONLY THE NAMES of the keys they need to fill in (e.g., DB_HOST=, DB_PASS=).
     It contains NO real passwords.

4. WHAT IS .GITIGNORE?
   - THE GATEKEEPER: A file named ".gitignore" tells Git which files or
     folders to IGNORE. Git will never "track" or upload these files to GitHub.
   - WHY IS .ENV INSIDE IT?: To prevent accidental leaks. By listing ".env"
     in the .gitignore file, Git will literally refuse to stage or commit it,
     keeping your real passwords safe on your local drive only.

================================================================================
SUMMARY:
- .env = Private, contains real secrets.
- .env.example = Public, contains an empty template.
- .gitignore = The security rule that keeps private files off of the internet.
================================================================================
