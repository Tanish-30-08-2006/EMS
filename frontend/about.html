About the Project

Employee Management System (EMS) is a full-stack, multi-tenant HR platform built from scratch — every table, every query, every API endpoint written by hand. No ORMs. No magic. Just Python, SQL, and a browser.

The system is built around schema-per-tenant isolation — the same architecture used by real SaaS companies like Notion, Linear, and Supabase itself. When a company signs up, they get their own private PostgreSQL schema. Their data is completely invisible to every other workspace on the system.

The schema is based on the classic Elmasri & Navathe company database from Fundamentals of Database Systems — the canonical textbook used in database courses worldwide. Every table you see here maps directly to a real concept taught in that book, extended with production-grade features: audit triggers, bcrypt passwords, email delivery, and CSV/JSON/Excel export.

🏛
Multi-Tenant Architecture
Each company gets a private PostgreSQL schema. Your data is invisible to every other workspace — enforced at the database level, not just in code.
🔐
Automatic Audit Trail
Every INSERT, UPDATE and DELETE is captured by PostgreSQL triggers automatically. No developer has to remember to log anything — the database does it for you.
🐍
Pure Python Backend
FastAPI for the REST layer, psycopg2 for direct SQL, bcrypt for passwords, smtplib for email delivery. Every operation is explicit and readable.
Database Schema

Six tables. Every relationship is deliberate. The schema stays true to the Elmasri & Navathe original while adding audit_log for change tracking and composite keys where entity integrity demands them.

employee
eno PK ename dob gender salary super_eno FK→employee dno FK→department
department
dno PK dname mgr_eno FK→employee mgrstartdate
project
pno PK pname plocation dno FK→department
works_on
eno PK (composite) pno PK (composite) hours eno FK→employee pno FK→project
dependent
eno PK (composite) dependent_name PK gender dob relationship eno FK→employee
dept_locations
dno PK (composite) dlocation PK dno FK→department

Acknowledgements

The database schema is modeled on the classic company database from Fundamentals of Database Systems by Ramez Elmasri and Shamkant B. Navathe — the book that defined how database courses are taught. If you've studied DBMS anywhere in the world, you've probably met James Borg and his employees.

The multi-tenant architecture is inspired by how Supabase organizes tenant schemas in PostgreSQL — one schema per tenant, connection routing by schema name. The audit trigger pattern is a standard PostgreSQL technique that captures row-level changes as JSONB before and after each operation.

This project was built as part of the Database Management Systems course at DAIICT, Gandhinagar.
